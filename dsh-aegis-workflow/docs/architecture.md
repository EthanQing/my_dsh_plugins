# Architecture

Task baseline: AEGIS-001 / P1, desktop DSH 0.2.1-rc.2. This document describes implemented configuration, not a separate orchestration engine.

The dsh-aegis-workflow package has a single bundle entry, disabled by default in the collection. Its Host apply function mounts the official Include on lib/presets.yml; scripts/build.mjs combines the seven original presets/*.patch.yml insert entries in their original order without changing their content. Each remains one `@deepseek-ai/dsh-agent-preset` declaration. The parent entry controls their shared activation/disposal; no custom scheduler, waiting loop, event delivery or state store is introduced. Lead mounts one `@deepseek-ai/dsh-tool-subagent` consumer with `toolName: aegis_delegate`, a default Planner preset, a six-id `allowedAgentPresets` enum, and `maxDepth: 1`; each call selects the child via `agent_preset`. Children contain no delegation tools. Host services remain owned by DSH; the bundle neither replaces the registry nor changes its default preset.

The local in-process spawn provider's `prepareContinuable` capability selects the official managed local lifecycle. Each child owns a session ID and its own prompt/tool composition. Completion releases its active instance. Official parent catalog projections and JSONL session persistence provide identity and restoration. `list_agents` reports running/inactive children; `send_message` accepts either state. Persistent history and a permanently running process are different things.

Planner, Coder, Reviewer and Git Operator mount the official `@deepseek-ai/dsh-tool-subagent-control` package, which provides adjacent `send_message` (parent ↔ direct child) and `interrupt_agent`, but no `list_agents` and no delegation. Knowledge Curator and Project Mentor are completion-only and do not mount the control package. A chat-capable child receives its parent id in the initial task guidance and can send a blocker, decision request or material risk while working; the completion notice remains the single final delivery. Messaging is exact-ID and adjacent; there is no broadcast or polling. `session_event_read` is recovery-only. The control package's `interrupt_agent` cannot target the parent or siblings and is inert in child presets without delegation.

Lead retains the task ID/version, workspace/baseline, approved scope, acceptance criteria, relevant user instructions, child IDs, valid evidence and cumulative rework in conversation. A detailed user/GPT brief is reused by reference after minimum critical fact/risk checks, rather than rewritten or copied into every handoff. If Planner is needed, its decision/plan addition stays in that child session; Reviewer gets the actual diff, assigned risk and existing evidence. Supplied opinions are not verified facts, and evidence is rechecked only where code changed, a contradiction appeared or the fact was not verified. This adds no persisted database or scheduler; role reuse never transfers approval to another task.

Task tiering is prompt routing. Small and clear-path normal tasks use Lead brief → user approval → Coder → brief Lead acceptance. Planner is invoked only for unresolved technical choices, requirements, dependency analysis or missing high-risk planning. Reviewer is required for high-risk work and otherwise used for a named unresolved correctness/safety risk or explicit user request. High-risk work retains a risk-aware plan and essential targeted verification; a supplied plan may be reused after its critical facts and safety assumptions are checked. Existing small-task size limits and high-risk triggers remain. Scope/risk growth stops affected writes and requires renewed approval. Detailed or long prompts do not override actual risk classification.

Coder owns implementation and sufficient verification using inherited file locations, evidence and criteria. Lead checks the actual scoped diff and valid results without duplicating Reviewer or rerunning checks. Curator, Mentor and Git Operator appear only when useful; pure knowledge tasks substitute Curator for Coder with risk-based planning/review. Approval and separate Git stage/commit/push authorization remain mandatory. Only useful independent read-only investigations may run concurrently; writers remain serial and no dependent verification or unapproved write is parallelized. No new roles, tool interfaces, forced phases or permissions are introduced. Rework retains the shared three-round ceiling and two-round no-progress stop.

Lead waiting is event-driven. After `aegis_delegate` returns an ID, Lead records the current assignment and does only useful independent work within its role and approved scope. With no such work remaining, it issues a brief status without tools and ends its current model turn, returning control to DSH without cancelling the workflow or requiring another user message. Shell sleep, fixed delays, shell loops, periodic catalog/history queries, and repeated Git/search/timestamp checks must not be used to wait for a child. Bounded checks for independent external-service readiness remain allowed. A completed `subagent-settled` notice is consumed once and advances the existing workflow, including its user approvals; no second completion confirmation or duplicate final-result request is made. Abnormal endings are not treated as success.

Read-only inspection of installed DSH 0.2.1-rc.2 confirms that `@deepseek-ai/dsh-tool-subagent` calls `startActivation` with `delivery: 'parent'`. `SubagentManager.notifySettlement` creates a `subagent-settled` message containing the ending status and closing result; `sendWaking` uses `followup` for an idle host-owned parent and `steer` for a running one. A resident managed parent also receives the manager's wake signal. This requires the exact live parent; unannounced/caller-delivered activations, parent replacement or host teardown have different delivery paths. These facts establish the normal notification route, not a guarantee across disconnects or a test of real-model compliance. The generic tool's suggestion that continuable children report results through `send_message` does not change Aegis's rule: important mid-work issues use messages, final delivery uses the official settlement notice.

Recovery is reserved for a real connection interruption, session recovery or missing result, after checking the available host delivery evidence; ordinary elapsed time is not evidence of delivery failure. Use a known child ID directly. If discovery is necessary, make at most one catalog lookup per incident. Desktop defaults to `openAt: never`, so full-text search remains optional. Raw `session_event_read` recovery uses `seq: 0, after: 50`, at most three advancing windows, followed by one exact-result read when found. Stop on no sequence progress or no later events; report unresolved evidence rather than polling or recreating the child. No index is enabled. Completed valid work is reused; file changes or Git commits are inspected before retries as appropriate, not as a completion detector. Cold restoration needs official session storage, currently registered matching preset IDs and exact workspace cwd equality for history queries. Restoring under a new bundle version loads its current preset definition.

All seven presets mount the same workspace tool set: read/write/edit file tools, file search, and the platform shell pair. Role separation is prompt-level: Planner investigates read-only, Reviewer reviews without editing, Curator writes knowledge only, Mentor teaches read-only, Lead coordinates without editing business files, and Git Operator performs only authorized Git operations. Reviewer is expected to use `git status`/`git diff`/`rg` rather than rereading whole files; the soft 20-30 tool-call budget is a ceiling, not a quota. These rules are not strict security enforcement. Shell itself can modify files and run Git, the Windows Git Bash executor may have different effective confinement semantics from the file tools (it reports `sandbox.enforcement`), and host sandbox/permissions plus user approval remain the real boundary. No custom command interceptor is included. An untrusted/misbehaving model requires host sandbox and permissions for stronger guarantees.

On Windows, the verified host is DSH desktop 0.2.1-rc.2 with `dsh-gitbash-shell` 0.38.5. The plugin withdraws `pwsh-sandbox`, installs a Git Bash `ctx.shell` executor (`bash.exe -c`), and, for an agent whose composed face has `pwsh` but no `bash`, mounts the official `tool-bash` and denies the fake `pwsh`. All seven presets keep the official per-platform tool row because it is the plugin's input; a static flip to `tool-bash` is unsafe on Windows profiles without that executor. This is host integration, not a bundle-owned shell implementation. The prompts also carry the temporary-artifact and minimal-verification rules; those remain behavioral, not enforced by DSH.

Development tests, fixtures and test runners have been removed from this repository. Historical verification records are retained separately. Only the minimal official-Include composition entry is shipped; preset behavior stays in YAML.
