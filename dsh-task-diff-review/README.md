# 代码改动概览与 Diff 审查

本轮出现实际文件改动后，才在输入框正上方显示文件数与增删行数。概览随输入框等宽缩放，展开可以看文件列表；点击文件，在已有右侧栏的同一个审查标签里查看 Diff。

右侧栏“开始”页提供“代码改动审查”入口，没有本轮改动也能查看 Git 差异。六种审查范围使用中文下拉菜单切换，不会分别创建标签页。

右侧栏有六个范围：

- **本轮对话**：从一条真实用户消息开始记录文件基线，对比此后工作区的净变化。DSH 子代理、多级子代理修改同一仓库的文件也会被记录，父代理先结束不会停止仍在运行的子代理记录。
- **未提交**：对比 HEAD 和当前磁盘文件，包括暂存、未暂存、未跟踪文件。以最终磁盘内容为准。
- **已暂存**：对比 HEAD 和 Index，只看已经放入暂存区的内容，不混入后续磁盘修改。
- **未暂存**：对比 Index 和磁盘文件，包括未暂存修改、删除和单独标识的未跟踪文件。
- **分支对比**：选择基准分支，比较 merge-base 到 HEAD 的已提交内容，不混入工作区修改。
- **历史提交**：选择分支，按提交历史浏览 Hash、标题、作者和时间；可搜索 Hash 前缀（至少 4 位）或完整提交信息，滚动到底部自动加载下一页，也可以点击“加载更多”。

点击历史提交可查看完整 Hash、提交说明、文件数和增删行数，再点击文件查看原生 Diff。Merge Commit 默认与第一个父提交比较，可以切换其他父提交；首个提交与空目录比较。选择历史分支不会 checkout，也不会改变当前工作区。

**未提交**始终直接比较 HEAD 与磁盘的净差异，不累加 Staged 和 Unstaged。六个 Review 范围仍然只读；写入操作集中在输入框上方的独立 Git 操作面板。

## Git 操作面板

输入框上方右侧会显示当前分支、未提交文件数、暂存/未暂存数量，以及默认推送目标的本地跟踪差异。状态自动更新；没有 Git 仓库时禁用操作。

胶囊挂在官方 `conversation.input.dock` 的独立正常流行，与输入卡片同宽；展开层相对该行向上生长，宽度最多 380px、高度最多 460px。侧栏开合和底部终端改变可用空间时，面板自然收窄并根据聊天滚动区剩余高度滚动，不使用视口固定定位或右侧栏偏移。上方空间不足时提示先缩小终端，避免操作面板被裁切。

- **暂存 / 取消暂存**：勾选文件后只操作选中项；不勾选时按钮明确显示“全部暂存 / 全部取消暂存”。支持新增、修改、删除和重命名。取消暂存仅改变 Index，保留磁盘代码，也支持同一文件同时存在暂存和未暂存修改。
- **提交**：弹窗显示分支、实际暂存区文件数及文本增删行数。可以手写多行信息，也可以点击“AI 生成提交信息”，让本会话最近使用的 DSH 模型根据真实暂存 Diff 生成中文 Conventional Commit。生成只填入文本，**点击“确认提交”才运行 Git Commit**，不会自动暂存其他文件。
- **推送**：自动读取已有 Remote 和 Push URL。只有一个 Remote 时直接显示名称；多个时可选择，默认优先分支 pushRemote、remote.pushDefault、分支 Remote，再选 origin。先点“检查推送目标”，查看实际目标分支与待推送数量，然后点“确认推送”。不修改 Remote 配置，不执行 Force Push、Pull、Rebase 或 Merge。

操作结束后自动刷新状态和 Review。提交确认绑定暂存区、分支与 HEAD；如果它们变了，需要重新预览。推送也会核对 Remote 配置和实际远端分支，拒绝过期确认或非快进推送。

操作以整个文件为单位，不提供按 Diff 行暂存。Detached HEAD 和未解决冲突需要先手动处理；插件不自动切分支或修复仓库。

AI 生成使用已有 DSH 模型服务，不需要额外 Key，也不会改动正在运行的代理或聊天上下文。没有可用会话模型、暂存 Diff 超过 128 KiB 或模型请求失败时，可以直接手写提交信息。点击 AI 按钮才发送暂存 Diff，不在后台自动调用模型。

推送复用系统 Git Credential Manager / 已有 Git 认证，不保存密码或 Token。折叠面板里的数量来自本地跟踪记录；推送前才联网核对实际远端。远端提交不在本地、没有权限、认证失败或分支分歧会明确提示，不自动 fetch 或修复。多 Push URL 分别显示数量；部分地址失败时请核对实际结果。Git 本身的 hooks、签名和 clean 过滤器会按原配置执行，插件不会跳过它们或在失败后自动回滚。

保留 DSH 原生 Diff 的行号、统一/左右对比、自动换行、代码高亮和文件打开功能。状态支持新增、修改、删除、重命名；二进制和过大文件明确标记，不计入可计算的行数。

## 怎么安装

从 GitHub 安装根合集 `github:EthanQing/my_dsh_plugins#main`，在“包含的组件”中打开 **代码改动概览与审查**。已有合集请由你更新。也可以使用根目录 `dist` 中单独的 `dsh-task-diff-review-0.3.2.tgz` 安装。

适配本机实际版本 **DSH 0.2.1-rc.2**。官方会话、子代理、右侧栏和交付物/Diff 组件需要保持开启。安装、启用和重启由你操作，本次开发没有修改 Desktop Profile。

**启用后开始一条新任务才能建立可信基线。** 插件无法倒推出安装前某条消息开始时的文件内容。历史任务可在右侧“任务”下拉框选择。

## 记录范围

- 本轮记录的是任务时间窗口内的净变化，无法保证区分 AI、用户和其他进程对同一工作区的并发写入。界面始终保留归属说明。
- 不读取 Git 忽略文件、符号链接/目录联接、子模块内容、仓库外文件。非 Git 目录和没有 HEAD 的“未提交”模式暂不支持。
- 子代理使用另一个可见 Git 仓库/工作树时，从首次观察到该子代理的工作目录开始建立额外基线，并提示此前变化未覆盖。外部工具自行启动、未关联到 DSH 的工作树不能保证发现。
- 每仓库最多 3000 个路径、每次捕获最多 64 MiB；2 MiB 以下文件保留内容和 Diff，2–16 MiB 文件保留内容指纹以确认变化并标记“过大”，不提供行数和正文。更大或无法读取的文件列入覆盖缺口，不冒充零改动。
- 捕获不是原子文件系统快照。捕获期间仍在变化的文件会提示，下次刷新再读取。长命令运行中依靠文件监听更新；监听不可用时可手动刷新。
- 未提交、未暂存比较按 Git 的 text/eol 与 core.autocrlf 设置处理 Windows 换行，避免把自动 CRLF 转换算成修改。外部 clean 过滤器、working-tree-encoding 和 ident 转换文件暂列覆盖缺口，不为计算 Diff 执行这些转换。Index 中的未解决冲突、链接和子模块也会提示未覆盖。
- 本轮结束后固定最后快照，不把随后用户独立修改算入该轮。运行中的子代理继续记录；后续完成通知唤起的 Lead 沿用原基线。Host 重启后保留已保存快照，重启中断的记录标记不完整，不虚构离线变化。

快照保存在 `%DSH_HOME%/plugin-data/dsh-task-diff-review`，未设置 DSH_HOME 时为 `%USERPROFILE%/.dsh/plugin-data/dsh-task-diff-review`。这是本地文件内容副本（不是 Git 提交），不上传；内容去重，总内容上限 512 MiB，达到上限会明确提示。若需清理，请退出 DSH 后由你删除该插件的数据目录；清理会失去历史 Diff。没有自动删除项目文件的功能。

## 与其他插件

新增自己的输入区条目、输入框上方右对齐 Git 行和审查标签，不替换官方 `changes-review`，不改 Markdown、消息编辑、子代理管理或折叠组件。只通过业务数据适配复用原生审查组件；如果以后 DSH 改动该组件契约，可能需要升级本插件。没有公开、稳定的独立 FileDiff 注册接口，不能承诺跨版本无修改兼容。

完整源码在本目录 `src/`，构建入口为 `scripts/build.mjs`，预构建文件在 `lib/`。维护时可使用已安装的 esbuild 0.25.12；构建不运行安装脚本。技术说明见 [docs/architecture.md](docs/architecture.md)。
