# dsh-codex-collapse

DSH Windows Desktop **0.2.1-rc.2** 的独立显示插件，版本 **0.1.0**。在当前仓库的 `dsh-codex-collapse/` 开发，未使用提示词中的旧机器路径，也未修改其他插件。

## 实现

- **每回合一个主要入口**：替换现有 `turn-process` 摘要，而不是追加另一张卡片。以回合为单位控制执行行，时间顺序和原始父子关系均由 DSH 保持；正文之间不再另建工作段折叠。
- **运行时紧凑进度**：根据公开 Chat Node 和工具生命周期显示读取、修改、搜索、命令/构建、子代理、等待输入等状态。读取/修改统计合并成功操作中明确给出的路径；不会把工具调用次数冒充文件数量。
- **正文保持可见**：不隐藏用户消息、AI 中途的正常文字说明、图片或最终回答。仅隐藏已识别的执行行和原生单独投影的 reasoning 部分，不隐藏 reasoning/正文混合的整条消息。
- **原始详情保留**：收起只通过按节点身份生成的 CSS 控制显示，不删除、移动或卸载原生消息/工具组件。展开后可继续使用原生工具项查看参数、输出和完整日志。
- **状态与手动选择**：运行和完成回合默认紧凑；完成状态只在实际转换时处理。用户手动展开后，流式更新、完成、切会话和重挂载都不会重置该选择。最多保留 300 个回合选择，使用窗口级 sessionStorage；关闭整个应用后不保证保留。
- **失败与等待优先**：错误工具项、原生错误消息、问答工具、显式提权请求和未知的运行中工具保持可见；停止显示“已停止”及上一步。Composer 的审批/输入区域完全不在隐藏范围内，不代替用户审批。
- 没有 DOM 文本扫描、MutationObserver、轮询、模拟点击、消息写回、会话事件写入或滚动位置回写。新增 CSS 仅匹配 DSH 的 flow / turn / node / reasoning 属性，且不会隐藏含键盘焦点的行。

## 安装前与首次使用

**由用户手动安装，本次开发未安装、启用或重启 DSH，也未修改 Profile。**

1. 在 DSH 插件管理中手动停用 `dsh-auto-collapse`。两套执行折叠不能同时使用，否则旧插件仍可能插入自己的工作段入口。本插件不会替你停用或卸载它。
2. 完全退出 Desktop，再使用 Desktop 自带 CLI 安装打包产物。以下是本机路径示例，其他机器自行替换：

   ```powershell
   & 'D:/Programs/DSH/resources/runtime/cli/bin/dsh.cmd' plugin --profile desktop add 'E:/Desktop/workspace/my_dsh_plugins/dsh-codex-collapse/dist/dsh-codex-collapse-0.1.0.tgz'
   ```

3. 自行重新打开 DSH。如工作详情不是 **全部展开（Verbose）**，插件会保留原生显示并提示切换。可点击摘要旁的“切换到全部展开”，或在 DSH 设置中自行选择。**这是适用于所有会话的原生显示偏好**，只有用户操作才更改，插件加载时不会自动修改。
4. 切换后由本插件提供单层折叠。再次更改原生详情模式时，本插件撤销隐藏样式并回退原生展示。

卸载后如希望恢复原生折叠，自行将工作详情还原为标准等模式；本插件不会自动撤销用户保存的显示偏好。本包已加入[仓库根合集](../README.md)，可以通过 `github:EthanQing/my_dsh_plugins#main` 安装或更新合集，再合并[启用示例](../examples/codex-collapse.patch.yml)。合集默认关闭此插件；合集与独立包二选一，避免重复安装。

## 为什么需要 Verbose

当前 DSH 原生 Turn Process 在运行/失败/停止时锁定展开，正常完成时又可能将中途正文与工作行一起折叠；原生 Step Group 还拥有独立的折叠状态。公开 Slots 没有针对这些容器的逐行策略接口。

本插件选择 **用户明确切换原生 Verbose + 复用现有控制插槽和原生详情组件**，避免篡改内核、劫持内部函数、重建 Chat Flow 或绕开插槽所有权。模式不符、接口缺失或插件报错时不注入隐藏 CSS，回退原生摘要和完整内容。

## 兼容与限制

- `dsh-message-edit-retry` 的用户消息、`turn-tail`、继续/重试按钮均未接管；`dsh-markdown-editor` 的消息渲染、长消息折叠与输入框也未接管。
- **不能与 dsh-auto-collapse 同时启用。** 当前 Profile 已检测到它，但本次没有变更其状态。
- 未识别工具/命令/插件节点优先保持可见，可能多留几行；已识别审批与问答保持原生交互。需要操作但没有公开状态的第三方自定义 UI，无法承诺自动识别。
- 未分出独立 reasoning 部分的混合消息不会整体隐藏；无明确回合归属的上下文不会被猜测归组。
- 文件数量仅统计成功工具明确声明的唯一路径，不推断 shell/run_code 的文件副作用；不把路径当作文件系统实际修改审计。错误/停止行始终可见，折叠不是消除错误。
- 折叠内的浏览器全文查找、复制页面所选文本需先展开。DSH 自身的消息复制与原始记录不受影响。
- 没有连接到 DSH 的浏览器控制/实时 Cordis inspection 工具，因此未声称完成 GUI 验收。已核对安装包及源码接口，基础模型、状态、CSS 范围、注册和打包检查由开发完成。

## 构建、检查与打包

运行产物已保存在 `lib/`，安装 `.tgz` 不需要执行构建脚本。依赖安装仍由开发者自行操作：

```powershell
npm ci
npm run build
npm run check
npm run pack:plugin
```

本次构建复用了工作区已有 esbuild，没有安装新依赖。`dist/` 包含独立 `.tgz` 和 `SHA256SUMS.txt`，不进入 Git。构建支持显式 `DSH_ESBUILD_MODULE` 模块 URL，未设置时使用本包锁定的开发依赖。

```text
src/             状态模型、折叠选择、React 控制器、局部 CSS、入口
lib/             可直接加载的 Host / Client 产物
locale/          中英文显示与元数据
scripts/         构建、产物一致性检查、独立打包
docs/            设计依据与已核对接口
cordis.patch.yml 独立插件行
icon.svg         原创 SVG 图标
```

接口核对与参考分析：[docs/design.md](docs/design.md)。
